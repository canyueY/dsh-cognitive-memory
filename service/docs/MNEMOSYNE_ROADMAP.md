# Mnemosyne 2.0 算法结构 Roadmap

> **口径：** 当前 2.0 统一版是仓库合并与版本统一，算法实现继承旧版；本文描述的是 **Roadmap 目标** 的算法结构，不把规划写成已交付。

## 1. 一句话结论

- **2.0：让记忆可信，让认知更新有依据。**
- **2.0 统一版：让 Node 与 DSH 插件收敛为一个交付单元，不新增认知算法。**
- **Roadmap 目标：让认知更新本身成为可发现、可验证、可优化、可追踪的过程。**

---

## 2. 笔记中的认知链

笔记里的核心链路可以抽象为：

```text
感觉登记 / 注意
      ↓
工作记忆（短时）
      ↓
长时记忆（情节 / 语义 / 程序）
      ↓
图式 / 认知地图（同化 / 顺应 / 平衡）
      ↓
提取 / 重构
      ↓
行动
      ↓
结果 / 反馈（经典条件作用 / 操作条件作用 / 观察学习）
      ↓
强化 / 替代强化 / 自我强化
      ↓
元认知与价值约束
      ↺
新的结构与策略
```

这条链对 Mnemosyne 的启发不是“再加几个模块”，而是补齐**从感知到结构、从反馈到策略、从局部更新到影响传播**的算法层。

---

## 3. Roadmap 算法结构：七层

| 层 | 名称 | 演化对象 | 对应笔记 | Roadmap 要补的能力 |
| --- | --- | --- | --- | --- |
| L0 | 感知与注意层 | 输入、显著性、编码 | 感觉登记、注意 | 注意力预算、显著性/新颖性、来源与情境编码 |
| L1 | 工作记忆层 | 当前活跃上下文 | 短时记忆、工作记忆 | 活跃集、容量与优先级、干扰抑制、上下文组装 |
| L2 | 长时记忆层 | 情节 / 语义 / 程序记忆 | 编码、存储、提取、遗忘 | 记忆类型区分、巩固、干扰/衰退、提取线索 |
| L3 | 图式与结构层 | 概念、关系、分类 | 图式、同化、顺应、平衡、认知地图 | 结构发现、假设生成、拆分/合并、结构验证 |
| L4 | 学习与强化层 | 反馈、策略、信用分配 | 经典/操作条件作用、强化程式、观察学习 | 策略评估、离线评估、替代强化、避免单一奖励 |
| L5 | 动机、情绪与价值层 | 目标、优先级、约束 | 需要、情绪、动机、价值 | 探索预算、风险门控、情绪作为情境而非标签 |
| L6 | 元认知与自我模型层 | 能力边界、置信、策略选择 | 元认知、自我调节 | 置信校准、何时检索/验证/询问、策略选择 |
| L7 | 社会规范层（长期） | 规范、观点采择、道德约束 | 道德发展三水平六阶段 | 只做约束与规范推理，不做阶段分类器；不进入 2.0 主线 |

> **L7 特别说明：** 道德发展理论可以帮助定义“不可牺牲的约束”，但不应把用户或 Agent 简化成“前习俗/习俗/后习俗”的标签。当前项目用权限、治理与价值约束表达 L5/L7，不新增人格裁判器。

---

## 4. 现有代码与目标层的差距

| 层 | 旧版 2.0 / 2.0 统一版已有 | 距离 Roadmap 还缺什么 |
| --- | --- | --- |
| L0 感知与注意 | Observation、证据来源、基础情绪抽取 | 显式注意力/显著性评分；输入预算；跨模态编码策略 |
| L1 工作记忆 | 检索、上下文组装、token budget | 活跃集状态、干扰抑制、工作记忆容量调度 |
| L2 长时记忆 | Memory Lifecycle、Bank、时间/状态、检索 | 情节/语义/程序分层；巩固与遗忘曲线；提取线索模型 |
| L3 图式与结构 | `schema_discovery`（启发式聚类）、`schema_ops`（同化/顺应）、`schema_network`（拆分/合并/影响） | 结构假设生成；结构收益验证；基于结果的拆分/合并决策 |
| L4 学习与强化 | `feedback_learning`、promote、reevaluate | 策略学习；信用分配；观察学习/离线评估；强化程式与风险约束 |
| L5 动机与价值 | 情绪提取/评估、治理与权限 | 探索预算、目标优先级、价值约束；情绪只作为情境变量 |
| L6 元认知 | `metacognition.reflect` / `analyze_impact` 基础钩子 | 置信校准、能力自我模型、策略选择闭环；从 stub 到可验证 |
| L7 社会规范 | Authority / grants / policy | 规范推理与价值约束；不把道德阶段做成主算法 |

**关键判断：** 2.0 统一版已经有“构件”，但还没有把构件闭合成“发现—假设—验证—传播—策略更新”的算法回路。

## 5. Roadmap 目标闭环

```text
Observation / Evidence / Memory
              ↓
        认知状态建模
              ↓
     结构发现与假设生成
              ↓
       认知依赖分析
              ↓
      候选结构 / 策略
              ↓
      离线评估与验证
              ↓
       权限与风险门控
              ↓
       受控应用变更
              ↓
       长期结果监测
              ↓
       元认知评估
              ↓
    更新结构发现与策略选择
```

这不是替换 2.0，而是在 2.0 的可信基础上增加四个闭环：

1. **结构闭环：** 发现结构缺陷 → 提出候选 → 验证收益；
2. **影响闭环：** 核心判断变化 → 依赖分析 → 下游重评；
3. **策略闭环：** 结果反馈 → 策略比较 → 受控选择；
4. **元认知闭环：** 监测自身表现 → 更新能力边界 → 调整策略。

---

## 6. 优先级

| 优先级 | 能力 | 验收问题 |
| --- | --- | --- |
| P0 | 认知结构发现与验证 | 能否发现原有结构缺陷，并证明新结构更好？ |
| P1 | 认知依赖图与影响传播 | 核心判断变化时，能否找出需要重评的下游结论？ |
| P2 | 元认知与策略学习 | 能否在不同情境下选择更合适的检索/推理/验证策略？ |
| P3 | 受控自主演化 | 能否在权限、风险与可逆性约束下分阶段开放自动化？ |

> 如果系统还不能判断一种结构是否更好，就不应该让它自主地大规模修改自己的结构。

---

## 7. 数据对象建议

在 2.0 的 `Observation / Evidence / Memory / Schema` 之外，Roadmap 目标需要新增：

| 对象 | 作用 |
| --- | --- |
| `StructureCandidate` | 待验证的结构假设（拆分/合并/抽象） |
| `StructureValidation` | 前后对比、回放结果、收益与成本 |
| `DependencyEdge` | 结论之间的依赖方向、强度、独立性 |
| `ImpactSet` | 变更影响的下游对象与重评任务 |
| `StrategyRecord` | 情境、策略、结果、成本、风险 |
| `SelfModel` | 能力边界、置信校准、历史失败模式 |
| `ValueConstraint` | 不可被收益覆盖的硬约束 |

这些对象仍应通过 Memory Bank、Authority 与审计管理，不另建第二套长期记忆系统。

---

## 8. 边界

- 不把“Roadmap 目标”写成已交付；当前 2.0 统一版只完成仓库合并与版本统一；
- 不把强化学习当成唯一答案；初期用统计评估、规则策略、Contextual Bandit 即可；
- 不把所有结果压成一个奖励分数；可信度、安全、隐私、可逆性是约束，不是可交易项；
- 不声称系统因此产生意识或真实情感；
- 不把道德发展阶段当成用户标签或 Agent 人格分类器。
